# Tools in Agent Cody Banks

> This file was created by Agent Cody Banks — the file itself and its contents were generated by reading the codebase's tool implementations and summarizing them.

All tools live in `agent/tools/` and implement the `ToolDefinition` interface from `agent/types.ts`. Each tool defines a Zod parameter schema and an async `execute` function that the agent loop (`agent/agent.ts`) dispatches. All file operations are guarded by `fs_guard.ts` to keep paths inside the workspace root (realpath of `process.cwd()`), rejecting `..` traversal and symlink escapes.

## Tool Contract

Every tool implements the `ToolDefinition` interface (`agent/types.ts`):

```typescript
interface ToolDefinition<TSchema extends z.ZodType> {
  type: "function"
  function: {
    name: string            // Wire name sent to the LLM
    description: string    // LLM-facing usage instructions
    label: string          // Human-readable display label
    parameters: TSchema     // Zod schema for runtime validation of arguments
    execute(toolId: string, params: z.output<TSchema>): Promise<ToolResult>
  }
}

interface ToolResult {
  tool_call_id: string
  content: string         // JSON-serialized response payload
  isError?: boolean       // true on any failure
}
```

The agent loop's `dispatchToolCall` (`agent/agent.ts:188`) handles dispatch uniformly: when the LLM requests a tool call, it finds the matching `ToolDefinition` by name, `safeParse`s the arguments against the Zod schema (returning an error result on validation failure), calls `execute`, catches exceptions, and appends the `ToolResult` to the message history as a `tool`-role message. The loop continues requesting LLM completions (up to `MAX_TOOL_ITERATIONS = 50` per turn) until the LLM stops requesting tool calls.

## Built-in Tools

| Tool | File | Description |
|------|------|-------------|
| **ls** | `agent/tools/ls.ts` | Lists files and directories (flat, no recursion) in a given path. Params: `path` (string), `showHidden` (boolean, default true). Caps at 200 entries and reports `truncated` in the response. |
| **read_file** | `agent/tools/read_file.ts` | Reads a text file with line numbers. Params: `path` (string), `offset` (int ≥1, optional), `limit` (int ≥1, optional). Defaults to 1000 lines. Detects binaries (1 KB NUL-byte sniff) and rejects files >1 MB. Returns `totalLineCount`, `offset`, `limit`, `truncated`, and `content` (array of `{lineNo, line}`). |
| **edit_file** | `agent/tools/edit_file.ts` | Batched atomic edits to an existing text file. Params: `path` (string), `ops` (array of discriminated-union ops). Four op kinds: `edit` (replace `[start,end)` column span on one line), `insert` (add text at a column), `delete` (remove N whole lines), `replace` (swap N lines for new text). All ops validated before any mutation; write-back via temp file + rename for crash safety. Rejects overlapping ops, out-of-range coordinates, surrogate-pair splits, binaries, and files >1 MB. Max 200 ops per call. |
| **simple_grep** | `agent/tools/grep.ts` | Regex search across workspace files using in-memory scanning. Params: `pattern` (string), `path` (string, optional — default cwd), `include` (glob, optional), `caseInsensitive` (boolean, default false), `contextLines` (0–10, default 2), `maxResults` (1–500, default 100). Uses fast-glob for file discovery; ignores `node_modules/`, `.git/`, `dist/`, `build/`, `.turbo/`, `*.log`. Returns `matches` (each with file, line, and context) and `truncated`. |
| **files** | `agent/tools/file.ts` | Batch create or delete files in the workspace. Params: `path` (array of strings), `function` (`"create"` or `"delete"`). `create` writes empty files with `wx` flag (fails if file exists); parent dirs created recursively; max 5 paths/call. `delete` removes files; max 2 paths/call. Paths processed independently — failures reported in `errors` array, don't block other paths. Symlink escape guarded via `realpath` on the deepest existing ancestor. |

## Shared Infrastructure

| Module | File | Description |
|--------|------|-----------|
| **fs_guard** | `agent/tools/fs_guard.ts` | Workspace containment guard. `resolveInsideRoot(inputPath)` resolves the path against the realpath of `process.cwd()` and rejects anything escaping via `..` or symlinks. `allowedRoot()` returns the symlink-free workspace root. Two-stage check: lexical `..` guard first, then `realpath` check for symlink escapes. Non-existent paths pass (returned to caller as-is) so `create` operations can target new files. |

## Error Handling

All tools follow a uniform error pattern:

- **Path guard failures**: returned as `{ error, path }` with `isError: true` — no exception thrown.
- **File-level failures** (missing, binary, oversized): returned as structured JSON with `isError: true`.
- **Per-op failures** (`edit_file`): the first failing op is reported as `{ index, function, error }` in the `edits` array; the file is not mutated (validation runs before write-back). `files` reports per-path errors in an `errors` array and continues processing remaining paths.
- **Unexpected exceptions**: caught by the agent loop in `dispatchToolCall`, wrapped as `{ error: "Execution error: ..." }` with `isError: true`, and surfaced to the LLM as a tool-role message so it can react.

## Adding a New Tool

1. Create `agent/tools/my_tool.ts`
2. Define a Zod schema for parameters
3. Export a `ToolDefinition` with `name`, `description`, `label`, `parameters`, and `execute`
4. Register it in the `available_tools` array in `agent/loop.ts:22`
5. Run `bun run lint:fix` and `bun run typecheck`

See the README's [Adding a New Tool](README.md#adding-a-new-tool) section for full details.
